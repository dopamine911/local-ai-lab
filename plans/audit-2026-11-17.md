## 3. Performance: batch size on `big` and `coder` was never tested
- Measured: marvin `big` reads a 32K prompt at 329 tok/s, the slowest number in the lab. It runs llama.cpp's
  default `-b 2048 -ub 512`. On the same marvin, `gpt-oss` went 557 → 820 tok/s (+47%) from `-ub 512` to 4096.
  On zaphod, `gpt-oss` lost 37% reading going from `-ub 2048` back to 512.
- Measured: marvin has 17 GB of memory available with `big` loaded, so a bigger ubatch (~1-3 GB) likely fits.
- Unverified: that `big` and `coder` gain the same way (a different model and MTP). A hypothesis to test.
- Listed twice already (CLAUDE.md next step 3, tuning/results.md idea 3), never run.
- Next: `big` `-ub 2048` (one change), `lab speed` before/after, then tool use if reading gains. Then `coder`.
- Good result: 32K reading +10% or more, writing within ±3%, tool use within the seed spread.
- Daniel decides: go-ahead (config reloads; check marvin is idle). Effort: ~1 h per model with tool use.
