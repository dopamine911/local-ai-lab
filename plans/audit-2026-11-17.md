## 3. Performance: batch size on `big` and `coder` was never tested
- Checked: marvin `big` reads a 32K prompt at 329 tok/s (today 354 / 328), the slowest number in the lab. Its model
  line has no `-b/-ub`, so llama.cpp's default `-b 2048 -ub 512` applies. Same for zaphod's `coder`.
- Docs: on marvin, `gpt-oss` went 557 → 820 tok/s 32K reading from `-ub 512` to 4096; on zaphod, `gpt-oss` lost 37%
  reading going from `-ub 2048` to 512.
- Checked: marvin has 17 GB available with `big` loaded, so a bigger ubatch (likely 1-3 GB) should fit.
- Unverified: that `big` and `coder` gain the same way (other models, with MTP). A hypothesis to test.
- Listed twice already (CLAUDE.md next step 3, tuning/results.md idea 3), never run.
- Next: `big` `-ub 2048` on its model line (not in `${server}`, which every model shares), `lab speed` before/after,
  then tool use if reading gains. Then `coder`.
- Good result: 32K reading +10% or more, writing within ±3%, tool use within the seed spread.
- Daniel decides: go-ahead (config reloads; check idle first). Effort: ~1 h per model with tool use.
